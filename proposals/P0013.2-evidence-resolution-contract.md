P0013.2: Evidence Resolution Contract

Status: Proposed
Date: 2026-09-15
Depends on: P0013 Historical Replay + Shared Analysis Contract

Objective

在 Analysis 与 Evidence Gap 之间增加一个稳定语义：

Context Missing ≠ Evidence Missing。

Agent 在声明 Evidence Gap 前，必须先判断所需证据是否已经被系统持有；如果已持有，应先 Retrieve 并继续分析。只有系统当前可访问 Evidence 中也不存在，才允许形成真正的 Evidence Gap，并进一步触发 World Acquisition。

Production 与 Historical Replay 使用同一规则；区别只在各自可访问的 Evidence 与 Business Time 边界。

Architecture
Analysis
   ↓
Evidence Need
   ↓
Evidence Resolution
   ├─ Context 已有
   │     ↓
   │   Analyze
   │
   ├─ Held Evidence 已有
   │     ↓
   │   Retrieve
   │     ↓
   │   Analyze
   │
   └─ Held Evidence 不存在
         ↓
      Evidence Gap
         ↓
      Fabric Acquisition
         ↓
       Evidence
         ↓
       Analyze

核心定义：

not_in_context  = Retrieval Need
not_in_evidence = Evidence Gap
Design

共享 Analysis Contract 增加一条硬约束：

在把某个分析维度标记为 gap 前，必须先完成 Evidence Resolution。

V1 Resolution 只需要区分三种结果：

IN_CONTEXT
RETRIEVED
UNAVAILABLE

其中：

IN_CONTEXT：当前 prompt 已有足够证据；
RETRIEVED：当前 prompt 不足，但已有 Evidence 可检索并成功取得；
UNAVAILABLE：系统持有证据仍无法回答，才可以生成 evidence_gap / acquisition_need。
首个验证 Binding：Order Evidence

不要做 Generic Evidence Resolver Framework。

只把现有 Order Evidence Access 接到这条 Contract 上，验证真实行为：

“完整价格带是什么？”
      ↓
当前摘要不足
      ↓
已有订单行？
      ↓ YES
retrieveOrders
      ↓
分析 81/34/46 条订单
      ↓
形成 Judgment

而：

“这个 ¥1596 订单是不是企业采购？”
      ↓
订单行无买家身份
      ↓
UNAVAILABLE
      ↓
真实 Evidence Gap
Time Boundary

Historical Replay 的 retrieval 必须继续满足：

Evidence.business_time <= Replay T

不得因为 retrieval 引入 future leakage。

Production 使用当前生产 Evidence 边界。

Boundaries
Included
共享 Evidence Resolution Contract。
Analysis 在声明 gap 前必须执行 Resolution。
将现有 Order Evidence Access 作为第一个真实 retrieval binding。
Agent 可访问订单明细 retrieval，不再是 operator-only。
Replay 保持 No-Future-Leak。
Resolution 结果进入 trajectory，能看到：
need
resolution
retrieved evidence refs
true gap
Production / Replay 共用同一语义 Contract。
NOT Included
不做 Generic Evidence Resolver Framework。
不为商品、广告、流量、库存等批量新增 retrieval。
不做新的 Capability Registry。
不修改 Acquisition Contract。
不修改 P0013.1 Historical Acquisition。
不修改 ADR-083 epistemic layers。
不修改 Business Time / No-Future-Leak。
不修改检测阈值或 Knowledge 内容。
不把所有原始订单塞进 prompt。
不允许 Agent 直接读任意磁盘文件绕过 Evidence Access。
不因为这次需求重构 MCP/Fabric tool system。
不解决退款、买家身份等源数据本身不存在的问题。
Success Criteria
Replay 中询问价格带、去顶 GMV/AOV、Top Orders、SKU 组合时，Agent 实际调用 Order Evidence Access，而不是直接报 gap。
Retrieved rows 满足 business_time <= T。
检索结果进入分析，并产生基于订单明细的结构 Judgment。
已有证据可以回答的问题不再进入 evidence_gaps。
退款、买家身份等源数据不存在的问题仍然诚实标记为真正 gap。
trajectory 能明确区分：
context miss → retrieval → evidence 与 true evidence gap。
Production / Replay 不产生两套 Analysis Contract。
用真实 Hermes Replay 场次验收，不能只用单测证明。
