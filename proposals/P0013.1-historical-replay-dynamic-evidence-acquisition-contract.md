# P0013.1: Historical Replay Dynamic Evidence Acquisition Contract

**Status**: Proposed
**Date**: 2026-09-13
**Depends on**: P0013 Historical Cognitive Replay, ADR-086

## Objective

为 Historical Replay 定义从**业务需求 → Evidence Coverage → Evidence Gap → 世界获取 → 可复用能力候选**的最小 Contract。

本阶段不建设通用 Capability Framework，而以 JD Historical Replay 为唯一 vertical slice，验证三个稳定边界：**Need Contract、Evidence Contract、Capability Persistence Contract**。

核心假设是：**Contract 描述“需要什么、什么算完成、成功方法如何被保留”，但不规定 Hermes 如何探索世界。**

第一次 Historical Acquisition 已证明 Hermes 可以在没有技术路径指导的情况下，自主发现 endpoint、CSRF、1000-row cap、按日切片及 `page.route` 等方法；但当时 Contract 只要求一次性 artifact，没有要求形成可复用能力。

---

## Background

当前 Workspace Historical Replay 依赖 frozen dataset：

```text
2026-08-04 ───────────── 2026-09-02
```

因此日期选择器只能在该数据集覆盖范围内工作。

第一次 Historical Acquisition 的真实 Contract 是：

> 指定 JD 店铺、近30天、订单明细 + 交易汇总，以任意合理方法获取真实数据，并保存 raw / parsed / provenance artifact。

Hermes 被允许使用 Python、Skill、Tool、MCP 等，但**没有被要求形成 reusable Tool / Skill / MCP / Capability**。

因此当前存在的是：

```text
Successful Exploration
        ↓
Successful Acquisition
        ↓
Frozen Artifacts
        ↓
9 experimental scripts

≠

Formal Reusable Capability
```

这不是 Hermes 未履约，而是第一次 Contract 没有定义能力沉淀。

---

## Architecture

```text
Historical Replay / Workspace
            │
            │ Need Contract
            ▼
          Fabric
            │
      Evidence Coverage
            │
       ┌────┴────┐
       │         │
   Sufficient    Gap
       │         │
       │         ▼
       │   Capability Resolution
       │         │
       │    ┌────┴─────┐
       │    │          │
       │ VERIFIED    MISSING
       │    │          │
       │ Execute     Hermes
       │    │        Explore
       │    │          │
       │    │      Working Method
       │    │          │
       │    │      Acquisition
       │    │          │
       │    │     Real Evidence
       │    │          │
       │    │    Capability Candidate
       │    │          │
       └────┴──────────┘
                 │
          Evidence Contract
                 ▼
          Frozen Dataset
                 │
          Dataset Catalog
                 │
                 ▼
         Historical Replay
```

关键边界：

> **Fabric 决定需要什么、缺什么、什么时候需要世界能力。**

> **Hermes 决定面对未知世界时如何探索和完成任务。**

> **MCP/Tool/Skill/Python/API/CDP 是执行机制，不是业务 Contract。**

---

## Design

### 1. Need Contract

Historical Replay 不发送“运行某个脚本”之类的实现指令。

它表达世界事实需求：

```text
HistoricalEvidenceNeed

subject:
  shop identity

source:
  jd

window:
  requested historical business-time range

domains:
  trade
  orders

purpose:
  historical_replay
```

Need Contract 必须保持业务语义。

它**不得包含**：

```text
endpoint
CSRF
page.route
pagination strategy
Python filename
TS function
CDP implementation
MCP tool name
```

这些属于 Binding/implementation。

---

### 2. Evidence Coverage / Gap

收到 Need 后，Fabric 首先检查已有 Dataset Catalog / Evidence Coverage。

概念关系：

```text
Need Window
    -
Existing Truthful Coverage
    =
Evidence Gap
```

例如：

```text
Need:
08-13 → 09-12

Existing:
08-04 → 09-02

Gap:
09-03 → 09-12
```

但 Gap 只是**需求缺口**，不能被解释成“JD一定可以提供这些日期”。

Provider Availability 仍然由真实 Acquisition 结果决定。

---

### 3. Evidence Contract

Hermes“拿到一些 JSON”不等于完成。

Historical Acquisition 至少必须返回：

```text
HistoricalEvidenceResult

requested_window
actual_window

domains:
  trade
  orders

completeness:
  complete | partial | unavailable

provenance:
  source system
  subject identity
  acquisition time
  source surfaces
  acquisition method
  raw artifact references

gaps:
  explicit uncovered / unavailable facts

dataset:
  canonical frozen artifact
```

原则：

> **requested_window 是 Need；actual_window 是世界事实。**

两者不得通过 normalization 被伪装成一致。

---

### 4. Capability Resolution

Fabric 在进入未知探索之前，必须先判断：

```text
Can an existing VERIFIED Binding satisfy this Need?
```

如果存在：

```text
HistoricalEvidenceNeed
        ↓
JD Binding
        ↓
Execute
```

不得无理由重新 Exploration。

如果不存在：

```text
HistoricalEvidenceNeed
        ↓
No verified binding
        ↓
Hermes Exploration
```

本阶段**不预设当前 9 个 Python scripts 已经构成 Binding**。

它们只是历史实验资产。

---

### 5. Hermes Exploration Contract

第一次面对未知/未正式绑定的世界时，Fabric 给 Hermes：

```text
Need Contract
+
Evidence Contract
+
Execution Boundaries
```

不提供具体技术攻略。

Hermes可以自主使用：

```text
existing Skill
existing Tool
existing script
MCP
browser
CDP
Python
API
new temporary Tool
```

并允许重新发现世界事实。

因此本阶段必须真实观察 Hermes 第二次面对 JD Historical Acquisition 时：

```text
是否发现以前的方法？
是否发现以前的 scripts？
是否复用？
是否部分重新探索？
是否完全重新探索？
形成了什么新的执行资产？
```

这些属于实验结果，Proposal **不预设答案**。

---

### 6. Capability Persistence Contract

这是本阶段新增的核心 Contract。

如果 Hermes 在满足 Need 的过程中形成了一个**已经真实执行成功、具有再次执行价值的方法**，任务结束不能只留下数据 artifact。

必须同时形成：

```text
CapabilityCandidate

satisfies:
  Need category

binding:
  source/system identity

input_contract:
  what it needs next time

output_contract:
  Evidence Contract produced

method:
  reusable method description

implementation_assets:
  actual Tool / Skill / script / MCP / other assets

dependencies:
  authentication
  browser/session
  external environment

verified_against:
  real execution evidence

limitations:
  known unsupported / unverified boundaries

provenance:
  how this candidate was created and verified
```

Candidate 表示：

> **“这里存在一个已经工作过、值得复用的方法。”**

不表示：

> **“它已经成为 Fabric 正式 Capability。”**

---

### 7. Promotion Boundary

Hermes **没有权限自行决定架构级 Promotion**。

生命周期在本阶段只做到：

```text
Explore
  ↓
Working Method
  ↓
Real Verification
  ↓
Capability Candidate
  ↓
STOP
```

之后：

```text
Candidate
   ↓
Human / Fabric architecture review
   ↓
Promote / Reject / Keep Experimental
```

Promotion 后最终执行载体可以是：

```text
MCP Tool
Hermes Skill
Python
TypeScript
Browser workflow
API adapter
other runtime
```

本阶段不规定必须转换成哪一种。

---

### 8. JD Vertical Slice

本阶段只使用当前 Historical Replay 的真实 JD case。

Workspace 请求一个超出现有 frozen dataset coverage 的合法历史窗口。

预期流程：

```text
Workspace
   ↓
HistoricalEvidenceNeed
   ↓
Catalog Coverage
   ↓
Gap
   ↓
Capability Resolution
   ↓
当前没有 Formal Historical Binding
   ↓
Hermes
   ↓
真实 Acquisition
   ↓
HistoricalEvidenceResult
   +
CapabilityCandidate
   ↓
Frozen Dataset
   ↓
Catalog
   ↓
Replay 可使用
```

具体请求窗口由运行时根据用户选择、已有 coverage 和 Provider Availability 确定；Proposal 不把 `09-03 → 09-12` 写死为实现常量。

---

### 9. Dataset Boundary

V1 不建设跨多个 frozen datasets 的组合系统。

当用户要求一个 Replay window，而已有 dataset 不能完整满足时，Acquisition 可以利用已有 Evidence 判断 Gap，但最终交付给 Replay 的必须仍然是一个**自洽、可验证的 frozen dataset product**。

不得让 Replay 自己理解：

```text
dataset A + dataset B + gap C
```

Dataset composition/merge 是独立问题，不在本阶段泛化。

同时不得修改现有：

```text
data/jd_acquisition_20260903_0834/
```

及其 manifest/hash。

---

## Boundaries

### Included

* 定义 `HistoricalEvidenceNeed`。
* 定义 Historical Evidence Result/完成语义。
* 定义 Evidence Coverage → Gap 关系。
* 定义 Capability Resolution 的最小语义。
* 定义缺少 verified Binding 时进入 Hermes Exploration。
* 定义 Capability Candidate Contract。
* 要求 Hermes 优先识别已有可复用资产，而不是默认重新探索。
* 保留第一次 acquisition 的实验 scripts 作为 reference assets。
* 用 JD Historical Replay 做一次真实 vertical-slice。
* 获取真实历史 Evidence。
* 产生真实 frozen dataset + machine provenance。
* 产生一个可审查的 Historical Acquisition Capability Candidate。
* Dataset Catalog 能发现最终合法 dataset。
* Historical Replay 能消费最终 dataset。
* 保存本次 Hermes trajectory，用于判断实际 capability persistence 行为。

### NOT Included (CRITICAL)

* **不接入淘宝。**
* **不接入抖音。**
* 不实现 generic Connector Factory。
* 不实现 generic Capability Framework。
* 不实现自动 Skill Creator。
* 不实现 Capability marketplace/registry platform。
* 不自动 Promotion。
* 不要求 Hermes 把 Candidate 强制转换为 MCP。
* 不要求 Python → TypeScript 重写。
* 不暴露所有 Hermes Tool/Skill 给 Fabric。
* 不把现有 9 个 scripts 直接宣布为正式 Capability。
* 不修改现有 frozen dataset 或历史 Replay runs。
* 不实现多个 dataset 的通用 merge/composition。
* 不修改 Replay cognition prompt。
* 不修改 ADR-083 Epistemic Integrity。
* 不修改 Business Time / No-Future-Leak 语义。
* 不实现后台定时历史数据刷新。
* 不实现 scheduler。
* 不实现多店铺抽象。
* 不做 Traffic reconstruction。
* 不处理 Hermes compression/600s rollover。
* 不处理 Reset residual data。
* 不处理 `[object Object]` metric-name defect。
* 不处理订单 child-line 缺失。
* 不处理 top-SKU grain labeling。
* 不修复无关 Exploration/MCP defects。
* **Workspace 不得通过“让用户在聊天框告诉 Hermes 去取数据”来完成此能力。**
* **Workspace 不得知道 Python、CDP、endpoint、MCP tool name 等 acquisition 实现细节。**

## Directory Structure

架构级预期，具体文件由 Claude 根据现有结构确定：

```text
Historical Replay
├── historical evidence need contract
├── coverage / gap resolution
└── dataset readiness integration

Fabric
├── capability resolution boundary
└── capability candidate contract

Historical Acquisition
├── preserved experimental JD assets
├── real execution binding/candidate assets
└── dataset freezer / provenance

Dataset Catalog
└── discover newly frozen dataset

context/
└── experiment acceptance / architecture decision
```

**不得为了符合此示意图而进行目录重构。**

## Success Criteria

1. Workspace 能表达一个超出现有 frozen dataset coverage 的 Historical Replay 时间需求，而不要求用户通过 chat 手工告诉 Hermes“去取数据”。

2. Fabric 能明确区分 `requested window`、`existing coverage`、`Evidence Gap` 和 `provider actual coverage`。

3. 当没有正式 Historical Acquisition Binding 时，系统能够把 **Need + Evidence Contract** 交给 Hermes，而不是把 JD endpoint/脚本攻略写进 Prompt。

4. Hermes 在真实执行中自主选择路径；最终报告能够证明它是复用了旧 Skill/Tool/script、部分重新探索，还是完全重新探索，**不得事后猜测**。

5. Acquisition 得到真实 JD historical trade + orders Evidence，并明确 actual coverage、completeness、provenance 和 gaps；不得以“API成功”代替业务语义验收。

6. 最终产生新的 canonical frozen dataset，且不修改现有 `08-04 → 09-02` frozen dataset及其 manifest/hash。

7. Dataset Catalog 能识别新 dataset，Historical Replay 能通过正常产品路径使用其合法时间窗口。

8. Hermes 成功形成的方法不能只存在于一次性执行 trajectory；必须输出一个符合本 Proposal 的 **Capability Candidate**，包含输入、输出、实现资产、依赖、真实验证证据和已知限制。

9. Candidate 不自动成为正式 Capability/MCP；Promotion 必须保持为独立架构决策。

10. 全程保留可审计 trajectory，能够回答：

```text
Need 是什么？
已有 Evidence 是什么？
Gap 是什么？
为什么进入 Exploration？
Hermes 已经知道什么？
Hermes 自己发现了什么？
复用了什么？
新建了什么？
什么真实证据证明 Acquisition 成功？
最后留下了什么可重复的方法？
```

11. 真实 Workspace vertical-slice 验收通过，而不仅是 unit/integration tests 通过。

12. 实验结束后必须能够回答下一阶段的核心架构问题：

> **对于另一个此前未知的 source，只替换 Binding/source，而保持 Need Contract 与 Evidence Contract 不变，这个模型是否仍然成立？**

本阶段**只回答这个问题，不实现第二个 source。**
